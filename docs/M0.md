# GRID M0 — Canonical Musical Domain Contract

Status: **frozen**. Implement against this. Do not add M1+ features until the test corpus below is green.

GRID is the canonical musical-library substrate.
MUSE is the intelligence/analysis layer.
N3X7 is a consumer of GRID + MUSE, not a co-owner of this schema.

Observation is not automatically canonical truth. Analysis may enrich. It may not silently overwrite.

A GRID canonical field may only change through a GRID-authorized domain operation.
Importers, plugins, and MUSE may propose. They do not redefine truth.

## Non-goals (M0)

- Real audio, beatgrids, stems, or waveform extraction
- Rekordbox / Serato / CSV import implementation
- MUSE analysis ingestion
- Hardening the plugin runner as a security isolate
- Multiplayer / P2P

M0 may _delete_ unused template surface. It may not add subsystems.

## 1. Identity and tenancy

- Runtime identity of a track is `(user_id, id)`.
- `id` is crate-local. It is not a global musical identity.
- A signed-in user MUST only read or mutate rows with their `user_id`.
- The `demo` crate is a shared public seed, not a tenant. Isolation tests use two real user ids, never demo-vs-user as the proof.
- Import-time identity (path, hash, ISRC, Rekordbox id) is reserved for M1. Do not invent it in M0.

## 2. Canonical track

GRID canonical facts live on the track row. Scales are DJ-library, not ML.

| Field             | Meaning                    | Invariant                                   |
| ----------------- | -------------------------- | ------------------------------------------- |
| `title`, `artist` | Required non-empty strings | trim, reject empty                          |
| `bpm`             | Canonical tempo            | `> 0`, typically 60–200                     |
| `camelot`         | Canonical key              | `/^(1[0-2]                                  | [1-9])[AB]$/` |
| `musical_key`     | Display key                | derived from Camelot when unset             |
| `energy`          | Peak-time intensity        | integer `0…10`                              |
| `danceability`    | Groove usefulness          | integer `0…10`                              |
| `rating`          | User rating                | integer `0…5`                               |
| `duration`        | Seconds                    | `> 0`                                       |
| `tags`            | User/system labels         | unique, case-preserving                     |
| `waveform`        | Preview amplitudes         | `number[]` length 0 or 64–512, values `0…1` |
| `cuepoints`       | See §6                     |                                             |

MUSE-style unit-interval values (`energy: 0.74`) are **not** GRID canonical. They belong on an enrichment record (M2).

### Provenance (schema reserved, not implemented in M0)

```
canonical.bpm          # what GRID acts on
source.bpm             # last human / import value
analysis.bpm           # last MUSE value
analysis.confidence    # 0..1
analysis.at            # timestamp
```

A write to `analysis.*` MUST NOT change `canonical.*` unless an explicit promote action says so.

## 3. Playlists / crates

- `type` ∈ `{ folder, playlist, smartlist }`.
- Folders contain playlists/folders, not tracks.
- Playlists own an ordered `trackIds` list. Membership is stored.
- A track may belong to many playlists.
- Deleting a playlist deletes membership rows, not tracks.
- `parent_id` must reference a folder in the same crate, or be null.

## 4. Smartlists

- Smartlists are **evaluated on read**. They are not materialized tables.
- Changing a rule or a matching track MUST change the next read result.
- Rules are AND-combined.
- Allowed fields: `genre`, `energy`, `rating`, `camelot`, `bpm`, `year`, `tag`.
- Allowed ops: `eq`, `gte`, `lte`, `contains`, `in`.

Fail semantics are **throw `DomainError`**, never silent match:

- known field + known operator + well-typed operand → evaluate
- unknown field → fail
- unknown operator → fail
- malformed operand → fail

## 5. Mix compatibility

The mix contract is `compatibleKeys` + `mixableFor` / `isMixablePair`.
`bpmCompatible` was a competing authority and has been deleted.

`compatibleKeys(id)` is the set:

- same Camelot slot
- ±1 around the wheel (12 ↔ 1)
- relative major/minor (`nA` ↔ `nB`)

`mixableFor(a, all)` contains `b` iff:

1. `a.id !== b.id`
2. `b.camelot ∈ compatibleKeys(a.camelot)`
3. `|a.bpm - b.bpm| ≤ 8`

Invariants:

- Compatibility is symmetric: `b ∈ mixableFor(a)` ⇔ `a ∈ mixableFor(b)`.
- `|bpm Δ| > 8` ⇒ not mixable, even if keys match.
- Double-time / half-time is **out of contract** until a later milestone names it.
- Sort order (closer BPM, then higher energy) is presentation, not membership.

## 6. Cuepoints

| Field       | Invariant                                      |
| ----------- | ---------------------------------------------- |
| `position`  | integer `0…7` (eight hotcue slots)             |
| `type`      | `"1"` hotcue, `"5"` loop (Lexicon wire values) |
| `startTime` | `0 ≤ startTime < duration`                     |
| `endTime`   | `null` for hotcues; `> startTime` for loops    |
| `name`      | non-empty                                      |
| `color`     | `#` + 6 hex                                    |

A track may have at most one cue per `position`.

## 7. REST contract (`/api/v1`)

Same-origin. Session user, else `demo`.

| Method | Path                     | Success                                      | Failure                                     |
| ------ | ------------------------ | -------------------------------------------- | ------------------------------------------- |
| GET    | `/tracks`                | `{ data: { total, limit, offset, tracks } }` | 500 only on server fault                    |
| GET    | `/track?id=`             | `{ data: { track } }`                        | 400 unknown / other-user id                 |
| PATCH  | `/track`                 | `{ data: { ok: true } }`                     | 400 missing id/edits; ignore unknown fields |
| GET    | `/search/tracks?filter=` | same list shape as `/tracks`                 | invalid JSON filter ⇒ empty filter, 200     |
| GET    | `/playlists`             | `{ data: { playlists } }`                    |                                             |
| GET    | `/playlist?id=`          | `{ data: { playlist } }`                     | 400                                         |
| POST   | `/playlist`              | `{ data: { id } }`                           | 400 no name                                 |
| PATCH  | `/playlist-tracks`       | `{ data: { ok: true } }`                     | 400                                         |
| GET    | `/` or `/openapi`        | catalog of endpoints                         |                                             |

Wire track uses Lexicon names: `albumTitle`, `key` (= Camelot), `archived` as `0|1`.

A request MUST NOT return another user's rows. 400, not an empty leak, for a known-other id.

## 8. Action runtime

`_library` / `_control` are a programmability surface, not a sandbox.

M0 requires:

- Actions only reach the crate through those APIs.
- Failed actions leave a readable error; they must not half-apply without saying so.
- No claim of isolation, CSP, or untrusted-plugin safety.

## 9. Import boundary (not implemented)

External source → adapter → GRID Import IR → validate → normalize → dedupe → Track.

IR is source-agnostic. Rekordbox XML, CSV, and future APIs do not write Rekordbox fields onto `Track`.

M0 only reserves the boundary. No adapter code.
